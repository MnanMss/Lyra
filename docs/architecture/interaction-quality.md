## 会话稳定性与性能

已有的分裂思考行 key、按需挂载和跟随滚动修复继续保留。真实回归验证重复切换不会累积孤立节点，
在同一份转录中滚动不会改变滚动条范围，展开状态和阅读位置会恢复，热缓存从首个绘制帧保持稳定。

本轮将后台会话事件折叠进已读缓存，避免每次后台消息都清掉缓存；冷读保留磁盘历史与读取期间的事件，
热读不能覆盖期间到达的新内容。会话缓存和展示状态分别限制为 12 份。页面 Activity 保留访问过的少量
分区，隐藏时暂停 effects；不是为每个会话保留完整隐藏 DOM。

问题导航的当前窗口内滚动统一为 420ms。跨历史窗口先挂载后定位，首帧不播放跨越未挂载内容的长距离滚动。
导航预览实测为 360×57px。刻度与侧栏缩放命中区错开，窄刻度轨道不叠加抢点击的滚动条。

独立慢 MCP 完成路径验证：创建后离开会话，后台仅生成一次回复；回访连续 20 帧都包含完整回复。
日志中只有一条 user 与一条 assistant，pendingPrompt 已清除。自动 worktree 改变执行路径，保留原会话 ID、
projectId 和初始化期间用户设置的标题。

## 自动 Skill 的真实环境结论

检查了用户环境中的两个既有候选，没有修改或启用它们：

- `release-version.md` 固定“6 个 package.json”和旧路径，把强制 Release dry run 降为推荐，固化旧发布操作。
- `dual-repo-release-sync.md` 绑定两个具体仓库的协作关系，应声明项目适用范围，不能当成跨项目通用流程。

进一步使用用户当前配置的 `@fast` 模型，从 37 份符合条件的真实会话中选择 4 份发布相关历史，进行
无工具调用的提案验证。第一次仅加强提示词仍生成了遗漏当前 AGENTS、手动 add/tag/push 的提案，
因此没有把“格式合格”当作语义合格。

修正输入链路后，生成过程读取当前项目指令。第二次真实生成耗时约 16.3 秒，结果为
`lyra-project-release`、scope=project，引用两个真实来源；要求每次重读 AGENTS，保留
`pnpm release:rehearse` 强制门禁，调用 `pnpm release`，禁止手工发布旁路、忽略检查和擅自回滚。
它不再固定包数量或当前版本。由于证据属于 Lyra 的专有发布流程，明确项目范围是正确结论。

portable 候选必须通过输入发现当前仓库的脚本、版本策略和约束；不能通过删掉可执行细节来伪装通用。
自动检查能约束结构、来源和记录格式，不能证明任意模型输出的语义都正确，候选仍需人审阅后启用。
本次真实生成结果只保存于临时验证目录；用户真实候选、MEMORY.md 和启用列表均未改动。

## 第 15 项：列表悬停删除

命令、独立技能和文件规则新增删除入口，MCP 与钩子的已有删除入口使用相同的行操作样式。
鼠标悬停时淡入，键盘焦点进入条目时显示，触摸设备常显；按钮始终占据固定位置，来源标签与
正文不因显隐而改变宽度或位置。沿用公共图标按钮、危险操作颜色和减少动态效果设置。

删除定义前显示确认框与完整路径。命令和规则文件移入系统废纸篓，技能连同整个目录和资源一起
移入废纸篓；符号链接只移走链接，不删除共享目标。不提供永久删除的降级路径。内置定义与插件
自带技能不提供单独删除入口，插件继续通过已有菜单卸载。MCP 和钩子保留原有配置删除、插件卸载行为。

主进程重新扫描已发现的定义，按文件路径精确定位，拒绝任意文件、内置标识或不再存在的条目。
同名定义不按名称批量删除；删除覆盖项后，下层同名定义可以重新成为当前有效项。操作期间禁用
对应按钮并防止重复请求；失败保留条目并显示原因。成功刷新列表及扩展计数，已运行会话通过原有
文件监听在安全回合边界更新能力。

本次真实 Electron 测试使用隔离 profile 中的合成命令、技能资源、规则、禁用 MCP 和钩子。
没有修改用户真实定义；退出后清理 profile 及测试自身放入系统废纸篓的 UUID 文件。
